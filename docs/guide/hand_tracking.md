# 손 추적: 웹캠에서 21개 점을 뽑고, 믿을 수 있는 만큼만 믿기

> 원문: `leap_hand_mapping/hand_tracker.py`, `ros2_ws/src/leap_teleop/leap_teleop/tracker_node.py`, `../design/teleop_pipeline.md`,
> `../history/phase1_retrospective.md`(녹화 오염, 손 위치 틀)

## 요약

- MediaPipe Hand Landmarker 가 주는 것(21점, 이미지 좌표 / world 좌표, handedness)과 **주지 않는 것**(절대 스케일, 정확한 깊이)을 정리한다.
- 손바닥 좌표계를 세워 카메라 자세와 무관한 입력을 만들 수 있다.
- 추적 품질을 **숫자로**(fps, 검출률, 랜드마크 떨림 mm) 재고, 거리·조명·거울상 문제를 가른다.

## 배경

MediaPipe 는 프레임마다 손 하나당 21개 랜드마크를 준다: 손목(0), 손가락마다 MCP·PIP·DIP·TIP 4개 × 5. 두 종류 좌표가 있다.

| | 이미지 랜드마크 | world 랜드마크 |
|---|---|---|
| 단위 | 정규화 픽셀 (x,y ∈ [0,1]) + 상대 z | **미터**(추정), 손 중심 원점 |
| 쓰임 | 화면 표시, 손 위치 틀 | **리타겟팅 입력** |
| 한계 | 깊이 없음 | 스케일이 "평균 손 크기" 가정에서 나와 **거리에 따라 변한다**; 손목 회전 자세에서 z 가 흔들린다 |

우리는 world 랜드마크를 쓰되, 절대 크기를 믿지 않는다 — `retargeting.md` 에서 손가락별로 다시 스케일한다.

### 손바닥 좌표계

원점 = 검지 MCP(5)와 약지 MCP(13)의 중점, y = 손가락이 뻗는 방향, x = 검지→약지, z = 외적. 로봇 쪽도 **같은 규칙**으로
URDF 영점 자세에서 세운다. 이러면 카메라 앞에서 손을 어떻게 들든 회전·평행이동이 상쇄된다.

### 거울상 함정

MediaPipe 의 handedness 는 입력이 거울상이 아니라고 가정한다. 셀피처럼 좌우 반전된 영상을 넣으면 라벨이 반대로 나오고
**world 좌표의 손 대칭도 같이 뒤집힌다** → 로봇 손이 손등 쪽으로 굽는다. 추적기는 라벨(`Right`)로 손을 고르므로, 오른손을
들었는데 안 잡히면 `mirror:=true`. **라벨 필터가 곧 좌표계 정합 검사다.**

### 손 위치 틀 (HandGuide)

랜드마크 잡음은 손이 화면에서 작을수록 커진다. 화면에 틀(가로 0.5W × 세로 0.8H)을 그리고, 손목→중지 MCP 픽셀 길이가
프레임 높이의 0.20~0.34 일 때만 초록으로 표시한다. **틀 안에서만 지표를 잰다.**

## 실행

```bash
conda activate leap-hand
bash scripts/phase1/p1_0_fetch_mediapipe_model.sh        # 최초 1회 (모델 7.5 MB)
python scripts/phase1/p1_1_check_hand_tracking.py        # 추적만: fps, 손바닥 폭 실측, 배율
# ROS2
source ros2_ws/install/setup.bash
ros2 launch leap_teleop sim.launch.py                    # tracker_node 로그에 fps / 검출 / 틀 밖
ros2 topic hz /hand/landmarks
```

### 예시 출력 — tracker_node

```
[tracker_node]:  29.3 fps  검출 748/882  틀 밖 20
```

### 예시 출력 — 정지 상태 랜드마크 떨림 (`p1_4`, `measurement.md`)

```
랜드마크 간격   표본 61  프레임간 변화 평균 0.47 mm  표준편차 평균 0.85 mm
```
(엄지 끝–검지 끝 거리의 프레임간 변화. 손을 가만히 든 채 잰 값.)

## 결과 읽는 법

- 30 fps 가 카메라 상한이다. MediaPipe 추론은 12 ms 라 병목이 아니다.
- "검출 748/882" — 검출 안 된 프레임은 publish 하지 않는다. 뒷단은 손 유실을 **시간**(1.5 s)으로 판단한다.
- 정지 떨림 0.85 mm 는 틀 안, 정면 조명 기준. 손을 멀리 두거나 역광이면 2 mm 를 넘고, 그게 `retargeting.md` 의 관절각 떨림으로 증폭된다.
- **손목을 돌리는 자세**(모양은 고정, 손바닥 방향만 회전)에서 관절각이 15° 넘게 흔들린다 — 단안 깊이의 한계. 이 프로젝트는
  그 자세를 범위 밖으로 뒀다.

## 사람 데이터부터 의심하라

리타겟터를 비교하려고 자세를 녹화했는데, **타이머 녹화**("핀치 3초")라 핀치 녹화의 2/3 가 손을 펴는 중이었다. 그 위에
쌓은 비교표가 전부 틀렸다. 고친 뒤(키 입력 녹화, 움직인 프레임 폐기) 결론이 뒤집혔다. 규칙: **녹화 데이터를 쓰기 전에
자세별 시계열(간격 mm, 프레임간 이동)을 먼저 본다.**
