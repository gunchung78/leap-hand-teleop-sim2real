# 측정으로 말하기: 지연·추종·계단 응답·떨림 분해

> 원문: `scripts/phase1/p1_4_teleop_metrics.py`, `p1_5_step_response.py`, `../design/ros2_twin.md`, `../history/phase1_retrospective.md`

## 요약

- "잘 따라온다"를 **네 개의 숫자**로 바꿀 수 있다: 종단 지연, 시뮬–실기 추종 오차, 계단 응답, 정지 떨림.
- 같은 스크립트를 돌려 이 저장소의 숫자를 **재현**하고, 다르면 어디가 다른지 좁힐 수 있다.
- 떨림을 "명령이 떠는가 / 모터가 떠는가 / 센서가 떠는가"로 **분해**한다.

## 배경 — 지표 네 가지

| 지표 | 정의 | 어떻게 재나 | 무엇을 말해 주나 |
|---|---|---|---|
| 종단 지연 | 카메라 촬영 → 관절 명령 발행 (ms) | `header.stamp` 전파 → `now − stamp` | 파이프라인이 얼마나 굼뜬가. 어느 단계 몫인지도(랜드마크 vs 명령 차이) |
| 시뮬–실기 추종 오차 | 같은 시각 `/sim` 과 `/real` 관절각 차이 RMS (deg) | 시각 정렬 후 관절별 RMS | 트윈이 실기를 얼마나 닮았나 |
| 계단 응답 | 관절 하나에 20° 계단 → 지연·상승(10→90%)·정상오차 | `p1_5`, 카메라 없이 (`tracker:=false`) | 모터+통신의 고유 성질. 리타겟과 무관 |
| 정지 떨림 | 손을 가만히 들었을 때 마지막 2 s 의 표준편차 | `p1_4` 의 마지막 블록 | 명령/실기/시뮬/랜드마크 중 **어디가 떠는지** |

핵심은 **분리**다. 카메라를 끄고 재면(계단) 리타겟이 빠지고, 명령과 실기를 따로 재면(떨림 분해) 모터가 빠진다. 한 숫자로
"느리다/떤다"고 하면 원인을 못 좁힌다.

## 실행

```bash
conda activate leap-hand && source ros2_ws/install/setup.bash
# A. 계단 응답 — 카메라 없이, 시뮬 (실기 있으면 real.launch.py tracker:=false 로 --source real)
ros2 launch leap_teleop sim.launch.py tracker:=false
python scripts/phase1/p1_5_step_response.py --source sim --joints if_mcp
# B. 라이브 지표 — 런치 띄우고 ROBOT ON, 15 s 자유롭게 움직이고 마지막 5 s 손 편 채 정지
python scripts/phase1/p1_4_teleop_metrics.py --seconds 20
```

## 결과 읽는 법

- 종단 32 ms = 추적 21.5 + 리타겟·전송 10.6. 리타겟이 35 ms 이던 시절(재시도 5회)엔 이 줄이 60 ms 였다 — 한 인자의 효과가
  **이 줄**에서 보인다.
- 시뮬 계단 지연 33 ms 는 60 Hz 물리 타이머 + 전송. 실기 83 ms 는 통신 왕복 + 모터 응답. 실기 정상오차 0.81° 는 백래시+P 제어.
- 시뮬에서만 `if_rot`/`mf_rot` 정상오차 5.9°(상승 없음) — 영점에서 20° 벌리면 옆 손가락과 충돌. 실기에선 없었다(실물 여유).
  `qpos` 를 직접 넣었다면 안 보였을 사실.
- 떨림 분해에서 **명령 0.75° < 실기 0.96°**: 모터가 명령 떨림을 약간 증폭. 엄지 `th_cmc` 만 3°/4.8° — 엄지 IK 잔차(30 mm+)가
  원인이지 모터가 아니다. 나머지 관절은 1° 안팎.
- 랜드마크 0.85 mm → 관절 명령 0.75°. 이 비율(mm → deg)이 리타겟의 **잡음 증폭률**이다.
