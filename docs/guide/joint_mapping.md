# 관절 매핑 함정: 시뮬 모델과 실기는 같은 로봇이 아니다

> 원문: `../design/joint_mapping.md`, `leap_hand_mapping/joint_map.py`, `scripts/phase0/p0_1_verify_mapping_fk.py`

## 요약

- "같은 로봇"의 두 모델(MuJoCo MJCF 와 실기 URDF)이 **관절 순서와 0점**에서 어떻게 다른지 설명한다.
- 매핑 후보가 맞는지 **순기구학(FK) 하나로** 판정하는 방법을 보인다 — 육안 대조 없이.
- "검증이 통과했는데 사실은 검증이 안 된" 두 가지 함정을 정리한다.

## 배경 — 왜 어긋나는가

로봇 손 하나에 모델 파일이 여럿이다. LEAP Hand 는:

| 모델 | 출처 | 관절 순서 (손가락마다) | 0점 |
|---|---|---|---|
| MuJoCo `right_hand.xml` | `mujoco_menagerie` ← `dexsuite/dex-urdf` 파생 | `mcp`(굽힘) → `rot`(벌림) → `pip` → `dip` | 편 손 = 0 |
| 실기 / 공식 URDF | `LEAP_Hand_API`, `Bidex_VisionPro_Teleop` | 모터 **0**(벌림) → **1**(굽힘) → 2 → 3 | 편 손 = **π** (모터 180°) |

즉 **손가락마다 앞 두 관절이 서로 바뀌어 있고**, 각도에는 π 오프셋이 있다. 엄지(12~15)는 순서가 같다.
이걸 모르고 MuJoCo 관절각 16개를 실기에 그대로 보내면, 굽혀야 할 손가락이 옆으로 벌어진다.

확정된 매핑은 치환 하나와 오프셋 하나다:

```
mujoco_to_motor = [1, 0, 2, 3,  5, 4, 6, 7,  9, 8, 10, 11,  12, 13, 14, 15]
실기 각도 = MuJoCo 각도(치환 뒤) + π
```

치환이 `(0 1)(4 5)(8 9)` 짝바꿈뿐이라 **자기 자신이 역치환**이다 — 코드에서 `MOTOR_TO_MUJOCO == MUJOCO_TO_MOTOR`.

## 배경 — 어떻게 "맞다"를 증명하나

인수인계 문서는 "관절을 하나씩 움직여 눈으로 대조"하라고 한다. 그건 실기가 있어야 하고, 사람 눈은 30° 와 34° 를 못
가른다. 대신 **두 모델에 같은 자세를 넣고 순기구학으로 손끝을 계산해 비교**한다.

두 가지 요령이 핵심이다:

1. **절대 좌표를 비교하지 않는다.** 두 모델은 베이스 프레임 규약이 다를 수 있다. 좌표계에 무관한 양 — **네 손끝 사이의
   쌍거리 6개** — 를 비교한다.
2. **평균이 아니라 표준편차로 판정한다.** 매핑이 맞으면 자세를 바꿔도 오차는 상수(모델 차이)로 남는다. 틀리면 자세마다
   오차가 요동친다. 그래서 무작위 자세 200개에서 오차의 **std** 가 지표다.

## 실행

```bash
conda activate leap-hand
python -m leap_hand_mapping.joint_map            # 매핑표 + 범위 + self_check
python scripts/phase0/p0_1_verify_mapping_fk.py  # FK 교차검증 (PyBullet headless, 1분 안팎)
```

```

  0 if_mcp   검지     1  [-0.314,+2.230]  [-0.314,+2.230]  [-0.314,+2.230]  [-0.314,+2.230]
  1 if_rot   검지     0  [-1.047,+1.047]  [-1.047,+1.047]  [-1.047,+1.047]  [-1.047,+0.052]
  ...
 13 th_axl   엄지    13  [-0.349,+2.094]  [-0.470,+2.443]  [-0.349,+2.094]  [-0.349,+2.094]

```

관찰: `if_rot` 의 모터 ID 가 0, `if_mcp` 가 1 — 이름 순서와 모터 순서가 다르다. 엄지 `th_axl`/`th_mcp` 는 **두 모델의
범위 자체가 다르다**(같은 로봇인데!). 그래서 실기에 보내기 전엔 항상 교집합(또는 더 좁은 표)으로 클립한다.

## 결과 읽는 법

- 채택안 std **0.06 mm** 대 차점 **25 mm** — 판정에 애매함이 없다. 좋은 검증 지표는 이렇게 **수백 배** 갈린다.
  두 후보가 2배 차이라면 지표를 의심할 것.
- `th_axl`(모터 13)만 손끝 이동이 **0.1 mm** 다. 엄지 축 회전은 회전축이 손끝을 거의 지나가서 이 지표로는 약하게만
  검증된다. 그래서 인접 관절과 뒤바뀐 후보(`엄지13-14뒤바꿈`)를 **따로 만들어** 배제했다. 지표의 사각지대는 후보를
  추가해 메운다.
- 실기 대조(`real_hand_safety.md`)에서 관절 종류별로 오차가 뭉친다(벌림 3.7°, 굽힘 1.7°, pip 0.8°, dip 0.8°). 매핑이 어긋나 있으면
  이렇게 정렬될 수 없다 — FK 와 독립적인 두 번째 확인.

## 함정 두 가지 (통과했는데 통과가 아닌 경우)

1. **말단 링크의 원점을 손끝으로 쓰면 안 된다.** 원점은 부모 관절(`dip`/`ipl`)이 움직여도 제자리라, 말단 4개 관절이
   지표에서 통째로 빠진다. 처음엔 이 상태로 "통과"가 떴다. → 관절마다 **단독 구동 이동량**을 같이 찍는 이유.
2. **두 모델의 "손끝"은 서로 다른 점이다.** URDF `realtip` 은 fingertip 프레임 + (20, −70, 15) mm 의 접촉점, MJCF `if_tip`
   은 메시 geom 중심. 그대로 비교하면 지렛대 길이가 달라 매핑과 무관한 20 mm 오차가 섞인다. 양쪽에 같은 오프셋을 줘야
   한다.
