# 리타겟팅: 사람 손 21점을 로봇 관절각 16개로

> 원문: `leap_hand_mapping/retarget.py`(7cccfdd 기반), `../design/teleop_pipeline.md`, `../history/phase1_retrospective.md`
> 1장(리타겟터 되돌리기), 3장 #8/#11

## 요약

- 왜 관절각을 **베끼지 않고** 손끝 위치로 IK 를 푸는지 설명한다.
- 손가락별 스케일, 손끝 목표점, 널스페이스, 시드/재시도가 각각 무엇을 해결하는지 안다.
- 리타겟터 옵션(`smoothing`, `deadband`, `restart_mm`, `pip_target`, `tip_mode`)을 바꿨을 때 **어떤 숫자가 어떻게 변하는지** 잰다.

## 배경

### 왜 IK 인가

사람 손과 LEAP 은 링크 길이·축 배치가 다르다(엄지는 특히). 관절각을 옮기면 손끝이 엉뚱한 곳에 간다. 조작에서 중요한 건
**손끝 위치**다. 그래서 사람 손끝(과 앞마디)을 로봇 손바닥 좌표계로 옮겨 **목표점**으로 삼고, 로봇 관절각을 IK 로 푼다.

### 파이프라인 (7cccfdd)

```
world 랜드마크 → 손바닥 좌표계(`hand_tracking.md`) → 손가락별 뿌리 정렬(로봇 mcp 링크 ↔ 사람 MCP) → 손가락별 길이 스케일
→ 목표점: 손가락당 [DIP 관절점, 손끝] (+ 옵션 PIP 점) → 자코비안 DLS IK (16×16 정규방정식, 관절 범위 강제)
→ 지수 평활 → 데드밴드 → 속도 제한 → 클립 → /leap/joint_cmd
```

- **손가락별 스케일**: 손바닥 폭 하나로 균일 스케일하면 사람의 손가락 비율이 로봇과 달라 손끝이 안 닿거나 넘친다.
  손가락마다 (사람 MCP→TIP 길이) 대 (로봇 길이) 비율을 쓴다.
- **손끝 목표의 길이는 로봇 것**: LEAP 의 `realtip` 은 fingertip 프레임에서 74 mm 떨어진 접촉점이라 스케일된 사람 손끝보다
  멀다. 방향만 사람에게서 받고 길이는 로봇 값을 쓴다 → 두 목표가 항상 동시에 도달 가능.
- **DLS 를 직접 구현한 이유**: PyBullet 내장 IK 는 널스페이스 인자를 주면 시드에 고정되고, 빼면 선형 수렴(30회에 1.25 mm).
  직접 구현 0.09 mm, 1.2 ms. 자코비안은 유한차분과 대조(상대오차 0.00%).
- **시드**: 영점에서 출발하면 크게 굽힌 손에서 국소최소(잔차 158 mm). 사람 손 관절각(랜드마크에서 직접 잰 굽힘/벌림)을
  시드로 쓰면 올바른 골짜기에서 출발한다. 엄지는 축 배치가 달라 이게 안 통해 재시도 시드 4개를 둔다.
- **재시도 임계 `restart_mm`**: 잔차가 이보다 크면 시드를 바꿔 다시 푼다. 7cccfdd 기본 1 mm 는 실제 손에서 **절대 못 미치는
  값**(정상 잔차 5~30 mm)이라 매 프레임 5회를 다 돌고, 프레임마다 이기는 해가 갈려 관절각이 튄다 → 떨림의 원인 하나.

### 널스페이스 — 목표점이 부족하면 생기는 일

손가락 하나에 관절 4개, 목표점이 2개(6 스칼라)면 과결정처럼 보이지만, 손끝만 맞추는 데는 여러 pip/dip 조합이 있다.
dex-retargeting 처럼 **손끝 벡터만** 목표로 잡으면 PIP 를 아예 안 쓰고 굽힘을 DIP 에 몰아넣는다(주먹이 아니라 갈고리).
우리 방식은 DIP 관절점을 목표에 넣어 MCP 가 널스페이스에서 빠져나오고, `pip_target` 옵션은 PIP 점까지 넣어 남은 자유도를 잡는다.

### 손끝점 두 가지 (`tip_mode`)

`realtip` 은 손가락 축에서 19.7° 벗어난 패드 접촉점(16° 옆, 12° 손바닥 쪽). 사람 손끝 랜드마크는 축 위의 점이라, 편 손에서
이 둘을 맞추려면 DIP 를 과굽힘한다. `axis` 는 로봇 손가락 축 위의 점(0, −70, 0 mm)을 손끝으로 쓴다. 라이브에서 `axis` 가 나았다.

## 실행

```bash
conda activate leap-hand
python scripts/phase1/p1_2_test_retarget_roundtrip.py       # 정답 있는 시험: 로봇 자세 → 가짜 랜드마크 → 리타겟 → 복원?
source ros2_ws/install/setup.bash
ros2 launch leap_teleop sim.launch.py                        # 기본값 (smoothing 0.2 deadband 1.0 restart_mm 50 pip_target true tip_mode axis)
ros2 launch leap_teleop sim.launch.py restart_mm:=1.0 pip_target:=false tip_mode:=realtip smoothing:=0.4 deadband:=0   # 7cccfdd 원래 값
```

### 예시 출력 — 왕복 시험 (무작위 자세 60개)

| 지표 | 평균 | 최대 |
|---|---:|---:|
| 손끝 잔차 | **0.09 mm** | 0.98 mm |
| 관절각 오차 | 1.42° | 62.14° |

### 예시 출력 — retarget_node 로그

```
[retarget_node]: 명령 453  리타겟 10.0 ms  촬영->명령 지연 31.8 ms  손끝잔차 12.0 mm  데드밴드 유지 228/453  재시도 0
```
(옛 기본값 restart_mm 1: 리타겟 35~38 ms, 재시도 5/프레임.)

## 결과 읽는 법

- 왕복 시험에서 관절각 최대 오차 62° 인데 손끝 잔차 0.98 mm — **중복성**이다. 판정은 손끝으로 한다. 이 시험은 좌표 변환과
  IK 가 맞물리는지만 보증한다; 사람↔로봇 비율 차이는 라이브로만 확인된다.
- 라이브 손끝 잔차 10~40 mm 는 "IK 가 못 푼 것"이 아니라 **목표가 로봇 작업공간 밖**인 경우가 대부분이다(엄지 30 mm+).
  증상이 IK 에 보여도 원인은 목표일 수 있다.
- `restart_mm` 1 → 50: 리타겟 35 → 10 ms, 재시도 5 → 0, 잔차는 그대로. 알고리즘은 같고 인자만 바꾼 것.

## 고칠수록 나빠진 날

오프라인 지표(녹화 npz 잔차)로 이긴 캘리브레이션 버전들이 **라이브에서 전부 졌다.** 배율과 엄지 회전을 시작 시점 거리에
고정하는데 MediaPipe 배율이 거리에 따라 변해서다. 그날 7cccfdd 로 되돌렸고 "이게 가장 잘된다". 규칙: **변경은 옵션으로,
기본값은 라이브로 확인한 뒤.**
